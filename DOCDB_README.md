# DocDB Backend Guide

Adobe Doc DB (`@adobe/aio-lib-db`) backend for the login-module. This is the **default** backend when `DB_TYPE` is unset or set to `docdb`.

---

## Overview

Adobe Doc DB is a managed document database provided by Adobe App Builder's Data Services. It stores JSON documents in collections with a MongoDB-like API. The adapter is at `actions/lib/db-adapters/docdb-adapter.js`.

### Key Characteristics

- **Document-oriented** — stores JSON documents with flexible schemas
- **Managed service** — provisioned and scaled by Adobe
- **IMS-authenticated** — requires an IMS access token for every connection
- **Region-scoped** — data is stored in a specific region (default: `apac`)
- **Namespace-scoped** — data is scoped to the I/O Runtime namespace

---

## Prerequisites

1. **Adobe Developer Console** — "App Builder Data Services" API must be enabled in your workspace
2. **IMS OAuth S2S credentials** — `IMS_OAUTH_S2S_CLIENT_ID`, `IMS_OAUTH_S2S_CLIENT_SECRET`, `IMS_OAUTH_S2S_ORG_ID`
3. **I/O Runtime namespace** — `AIO_runtime_namespace` (set by `aio app use`)
4. **Scopes** — `adobeio.abdata.read`, `adobeio.abdata.write`, `adobeio.abdata.manage` included in `IMS_OAUTH_S2S_SCOPES`

---

## Environment Variables

| Variable | Required | Description |
|---|---|---|
| `DB_TYPE` | No | Set to `docdb` or leave unset (default) |
| `AIO_runtime_namespace` | Yes | I/O Runtime namespace (set by `aio app use`) |
| `IMS_OAUTH_S2S_CLIENT_ID` | Yes | OAuth S2S client ID |
| `IMS_OAUTH_S2S_CLIENT_SECRET` | Yes | OAuth S2S client secret |
| `IMS_OAUTH_S2S_ORG_ID` | Yes | IMS organization ID |
| `IMS_OAUTH_S2S_SCOPES` | Yes | OAuth scopes (JSON array including `adobeio.abdata.*`) |
| `AIO_DB_REGION` | No | DocDB region (default: `apac`) |

All credentials are auto-generated by `aio app use`.

```bash
aio app use
```


## How It Works

### Connection Flow

1. `db.js` calls `getAdapter(params)` → returns docdb-adapter
2. `docdb-adapter.connect(params)` resolves an IMS access token:
   - If `params.AIO_DB_TOKEN` is provided, uses it directly
   - Otherwise, calls `generateAccessToken()` with IMS S2S credentials
3. Calls `libDB.init({ region, token, namespace })` → connects to DocDB
4. Returns `{ dbClient }` with the unified interface

### IMS Token Resolution

| Context | Token Source |
|---|---|
| **Local dev** (`aio app dev`) | `imsHelper.js` generates a token from `.env` S2S credentials |
| **I/O Runtime (deployed)** | Token passed via `Authorization` header or generated from action params |
| **setup-db.js script** | Generates token directly from `.env` S2S credentials |

### Adapter Interface

```javascript
const { dbClient } = await adapter.connect(params)

// Collection operations
const col = dbClient.collection('otps')
await col.findOne({ otpReferenceId: 'otp_123' })    // throws 'Document not found' if missing
await col.insertOne({ otpReferenceId: 'otp_123', otp: '1234', ... })
await col.updateOne({ _id: 'key' }, { $set: { field: 'value' } }, { upsert: true })
await col.deleteOne({ otpReferenceId: 'otp_123' })
await col.createIndex({ email: 1 }, { unique: true, name: 'uniq_email' })
await col.getIndexes()

// Admin operations
await dbClient.createCollection('new_collection')
await dbClient.listCollections()  // → [{ name: 'app_config' }, ...]
await dbClient.close()
```

## Collections

### `app_config`

Singleton document (`_id: 'app_config'`) holding module configuration.

```json
{
  "_id": "app_config",
  "is_enabled": true,
  "otp_expiration_validity": 10,
  "otp_in_response": false,
  "auto_register": false,
  "allow_key_info_update": false,
  "updatedAt": 1711017600000
}
```

### `otps`

Temporary OTP records. Documents are keyed by `otpReferenceId`.

```json
{
  "otpReferenceId": "otp_1711017600000_12345",
  "otp": "4821",
  "operation": "login",
  "loginType": "email",
  "email": "customer@example.com",
  "firstname": "John",
  "lastname": "Doe",
  "createdAt": 1711017600000,
  "expiresAt": 1711018200000,
  "otpExpirationValidityMinutes": 10,
  "consumed": false
}
```

### `customer_mobile_identity`

Customer identity mapping. Has unique indexes on `email`, `mobile_number`, and `customer_id`.

```json
{
  "email": "customer@example.com",
  "mobile_number": "+919876543210",
  "customer_id": 42,
  "login_type": "both",
  "status": "active",
  "firstname": "John",
  "lastname": "Doe",
  "created_at": "2024-03-21T12:00:00.000Z",
  "updated_at": "2024-03-21T12:00:00.000Z"
}
```

## Error Behavior

| Scenario | DocDB Behavior | Error Code |
|---|---|---|
| Document not found | Throws `"Document not found"` | — |
| Duplicate unique key | Throws with `code: 11000` | 11000 |
| Collection not found | Throws `"collection not found"` | — |
| Token expired/invalid | HTTP 401/403 | 401/403 |

The `db.js` facade provides error classifiers (`isDocumentNotFoundError`, `isUniqueConstraintError`, etc.) that normalize these for both backends.

## Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| `Runtime namespace is required` | `AIO_runtime_namespace` or `__OW_NAMESPACE` not set | Run `aio app use` to regenerate `.env` |
| `database token missing` | IMS credentials missing or invalid | Verify `IMS_OAUTH_S2S_*` vars in `.env`; ensure "App Builder Data Services" API is enabled |
| `401 Unauthorized` from DocDB | Token expired or wrong scopes | Regenerate token; ensure scopes include `adobeio.abdata.*` |
| `collection not found` | Collection not created | Run `npm run setup-db` |
| Slow connections | Region mismatch | Set `AIO_DB_REGION` to match your Commerce instance region |

## Switching to MySQL

To switch from DocDB to MySQL, set `DB_TYPE=mysql` in your `.env` and configure the MySQL connection variables. See [MYSQL_README.md](MYSQL_README.md) for details. No code changes are required — the adapter factory handles the switch automatically.
